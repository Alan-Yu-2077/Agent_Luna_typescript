# v0.32.1 — Skills into semantic recall + usage tracking + the embed-key fix

> **Status: ✅ SHIPPED 2026-07-04** (mainline; see DEVELOPMENT.md v0.32.1). Review-driven
> deviations from this plan, all adversarially confirmed then fixed: skills are
> **relevance-gated with no recency term** (the plan's plain `SKILL_IMPORTANCE + verified_ms`
> candidate would have let fresh zero-relevance skills outrank relevant memories and flood the
> hot-path top-12 for ~11h per save — empirically reproduced); candidate `t_ms` is
> **`created_ms`**, not `verified_ms` (a re-verify must not rewrite the "when it happened"
> label); the gate is a **boot-frozen `setSkillsRecallMounted`** set beside the registry
> composition, NOT a call-time `skillsEnabled()` env read (a live settings pin would have
> half-applied skills — pointers surfacing while `recall_skill` stayed unmounted); the recall
> tool returns an honest disabled error for a skills scope in a skills-off boot; and migration
> `0019` resets the mixed-key `embeddings_cache` (the old `contentHash` rows are
> indistinguishable orphans).
>
> Original banner: **Status: PLANNED.** Initiative: Skills as Procedural Memory (Order 23,
> version 2/4). Risk: **Low** (extends a proven substrate along its own template; one
> pre-existing bug fixed). Depends: v0.32.0. Flag: none new — the candidate loop gates on the
> existing `skillsEnabled()` (`LUNA_SKILLS=0` kills the whole feature family).

## Goal

Make skills findable the way the rest of memory is findable. After this version a relevant skill
surfaces **by meaning** in the per-turn auto-recall (a paraphrased task matches a skill whose
stored wording differs — closing the audited "lexical-only, blind-guess" gap), the agentic
`recall` tool can scope to skills, and every recall of a skill leaves a usage trace
(`used_count`/`last_used_ms`) — the signal v0.32.0's shelf eviction and v0.32.2's dream
deprecation both read. Also fixes the pre-existing rag_refresh embed-key mismatch so dream-time
pre-warming actually warms what recall reads.

## What ships

### `packages/server/src/memory/recall/recall.ts` — the fourth source

Template: the diary source addition (v0.17.1; candidate loop at `recall.ts:116-124`).

- Extend the closed union `'l2' | 'l3' | 'diary'` with `'skills'` in **all three places**:
  `Hit.source` (:34), `Candidate.source` (:80), `opts.sources` (:145).
- `SKILL_IMPORTANCE = 0.75` beside `DEFAULT_IMPORTANCE`/`DIARY_IMPORTANCE` (:30-31) — a skill is
  distilled procedure, slightly above diary (0.7): it exists *because* it proved reusable.
- `collectCandidates` gains a loop over active skills (gated on `skillsEnabled()`):
  `source: 'skills'`, `id: \`skill:${name}\``, **`text: \`${name}: ${description}\`` — the
  retrieval key is name+description (the Voyager pattern), NOT the body**. The hit surfaces the
  pointer; the L1 clause (v0.32.0) directs her to `recall_skill` for the full body. This keeps
  the auto-recall block small and makes the description quality do the work.
  `t_ms: verified_ms`, `importance: SKILL_IMPORTANCE`. Deprecated skills excluded
  (`includeDeprecated=false` from v0.32.0).
- Embedding comes free: `retrieve()` lazily embeds cold candidates via `embedCacheKey`
  (:176-188, `MAX_EMBED_PER_TURN=64`) — no new plumbing.

### `packages/server/src/tools/builtin/recall.ts` — expose without breaking validation

- `RecallHit.source` enum `['l2','l3','diary']` → `+ 'skills'` (:24) — without this, skill hits
  **fail the tool's own output validation at runtime** (the closed-enum pitfall).
- Scope enum `['facts','timeline','both']` (:12-18) → `+ 'skills'`; mapping: `'skills'` →
  `sources: ['skills']`; `'both'` → all four. `'facts'`/`'timeline'` unchanged (procedures are
  neither durable facts nor episodes). Update the scope `.describe()` text.

### `packages/server/src/tools/builtin/recall_skill.ts` — usage tracking

- Each skill actually returned → `markUsed(name, Date.now())` (the epoch-silent store function
  from v0.32.0). A miss (no hits) records nothing.
- Optional polish: `searchSkills` keeps lexical ranking here (the tool's contract is unchanged);
  semantic reach now comes from the recall side, so no embeddings work in this tool.

### `packages/server/src/dream/cycle.ts` — rag_refresh fixes (pre-existing bug + skills)

- **Fix the key mismatch**: the pre-warm's miss-check and insert key on `contentHash(text)`
  (`cycle.ts:346,356`) while `retrieve()` reads/writes `embedCacheKey(text)` (model-namespaced,
  `embed.ts:66-68`) — the warmed vectors are unreadable by recall (dead work since v0.20.5).
  Switch both sites to `embedCacheKey`. Regression test proves warm-then-retrieve embeds nothing
  new.
- Add active skills' `\`${name}: ${description}\`` texts to the pre-warm set (the text-gathering
  loop at `cycle.ts:338-343`) — same strings the candidate loop uses, so the cache key matches.

## Tests

- **Semantic reach (the headline)**: with a mocked embed client, a query paraphrasing a skill's
  purpose (zero lexical token overlap with name+description) returns the `skills` hit from
  `retrieve()`; lexical-only fallback (no vectors) still finds token-overlapping skills.
- **Scoping**: `retrieve(..., {sources:['skills']})` returns only skills; default (no `sources`)
  now includes skills alongside l2/l3/diary; deprecated skills never appear.
- **Recall tool**: scope `'skills'` round-trips; a skills hit passes output validation
  (the enum extension); scope `'both'` includes all four sources.
- **Usage**: `recall_skill` returning N skills bumps each `used_count` by 1 + stamps
  `last_used_ms`; a miss bumps nothing; `markUsed` does not bump the memory epoch (cache
  invariant guard).
- **Embed-key regression**: run the (fixed) rag_refresh pre-warm, then `retrieve()` with a live
  embed-call counter — zero cold embeds for pre-warmed texts (proves the keys now match); the
  old behavior (mismatched keys) is pinned dead by this test.
- Hot-path shape: with `LUNA_SKILLS=0`, `collectCandidates` is byte-identical to v0.32.0
  behavior (no skills source) — the kill switch kills recall presence too.
- Full `bun test` green; `tsc` clean.

## What this version explicitly does NOT include

- Any dream-side skill writing → v0.32.2 (this version only makes rag_refresh *read* skills for
  pre-warming).
- Shelf/render changes — v0.32.0's shelf is untouched; only findability changes.
- Embedding the skill **body** — the retrieval key stays name+description by design; revisit
  only if lived usage shows misses (note for a future initiative, not v0.32.2).

## Risk

- **Auto-recall dilution**: skills now compete for the top-k of the hot-path recall block. Bound:
  the corpus is tiny (1 today; capped growth in v0.32.2), `sources` pre-filtering (v0.20.5)
  keeps scoped queries clean, and importance 0.75 only wins when relevance agrees. Watch item,
  not a gate.
- **Closed-enum drift**: the recall tool's enum extension is load-bearing (runtime validation
  failure otherwise) — pinned by test.
- **rag_refresh fix touches shipped dream behavior**: strictly a correction toward the
  documented intent (v0.20.5 introduced the namespaced key); the regression test pins both
  directions.

## Acceptance criteria

- [ ] `'skills'` is a first-class `retrieve()` source (all three unions + candidate loop +
      importance const); paraphrase-match test passes.
- [ ] The recall tool exposes skills (scope + output enum) without validation failures.
- [ ] `recall_skill` hits bump `used_count`/`last_used_ms`; epoch-silent, audit-silent.
- [ ] rag_refresh warms under `embedCacheKey` (bug fixed, regression-pinned) and includes skill

- [ ] `LUNA_SKILLS=0` removes skills from candidates entirely.
- [ ] Full suite green; `tsc` clean.

## Notes for v0.32.2 (don't foreclose)

- The candidate text format `\`${name}: ${description}\`` is now a contract shared by the
  candidate loop and rag_refresh's pre-warm — the dream distillation step must reuse the same
  string builder (export a `skillEmbedText(skill)` helper) or the cache splits.
- `used_count`/`last_used_ms` are now live signals — v0.32.2's deprecation heuristic reads them;
  don't reset them on `saveSkill` updates (an improved skill keeps its usage history).
