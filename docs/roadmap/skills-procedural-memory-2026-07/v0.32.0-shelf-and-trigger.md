# v0.32.0 — Lifecycle substrate + the skill shelf + the L1 trigger

> **Status: PLANNED.** Initiative: Skills as Procedural Memory (Order 23, version 1/4). Risk:
> **Low-Medium** (touches the cached system block + a schema migration; no self-authoring yet).
> Depends: nothing. Flag: `LUNA_SKILL_SHELF` (default **ON**, `=0` escape hatch — the shelf is
> additive + deterministic; precedent: v0.29.0's default-on-with-hatch). Skill tools themselves
> stay behind the existing `LUNA_SKILLS` (default ON).

## Goal

Close the two audited open loops **for the awake path** in one version: after this ships, Luna
(a) *sees* her skill library every turn (the shelf — names + descriptions in the cached system
block), and (b) is *told* when to consult it and when to grow it (the L1 skills clause). Beneath
that, land the lifecycle substrate every later version builds on: audit trail, usage counters,
provenance, deprecation, no-op guard, epoch bump. This version alone should move the system from
"1 save + 4 recalls in 19 days" to a living library.

## What ships

### Migration `packages/server/src/migrations/0018_skills_lifecycle.sql`

Never edits `0009_skills.sql`; forward-only:

```sql
-- Audit: the prior state of a skill BEFORE every mutating write (update/deprecate/restore).
-- A fresh insert (no prior row) writes no audit row — same semantics as soul_audit.
CREATE TABLE IF NOT EXISTS skills_audit (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  t_ms             INTEGER NOT NULL,
  name             TEXT NOT NULL,
  prev_description TEXT NOT NULL,
  prev_body        TEXT NOT NULL,
  prev_source      TEXT NOT NULL,
  prev_deprecated_ms INTEGER NOT NULL,
  source           TEXT NOT NULL            -- who wrote: 'save_skill' | 'dream' | 'owner' | 'restore'
);
CREATE INDEX IF NOT EXISTS idx_skills_audit_name ON skills_audit (name, id);

ALTER TABLE skills ADD COLUMN used_count    INTEGER NOT NULL DEFAULT 0;
ALTER TABLE skills ADD COLUMN last_used_ms  INTEGER NOT NULL DEFAULT 0;
ALTER TABLE skills ADD COLUMN source        TEXT    NOT NULL DEFAULT 'saved';
ALTER TABLE skills ADD COLUMN deprecated_ms INTEGER NOT NULL DEFAULT 0;  -- 0 = active
```

The live DB's one existing row (`discover-latest-build`) backfills to
`used_count=0, source='saved', deprecated_ms=0` — verified in the migration test.

### `packages/server/src/skills/skillStore.ts` — lifecycle rework

Template: `soulStore.updateEvolving` (audit-first, byte-identical no-op guard, epoch bump on
real change — `soulStore.ts:64-84`).

- `saveSkill(skill, nowMs, source: 'save_skill' | 'dream' | 'owner' = 'save_skill')`:
  - **No-op guard**: identical `description` + `body` on an existing active row → return without
    write, audit, or epoch bump (protects the cache invariant).
  - **Audit-first**: when a prior row exists, insert its full prior state into `skills_audit`
    BEFORE the upsert (the current destructive upsert at `skillStore.ts:32-51` loses history —
    that ends here).
  - **`bumpMemoryEpoch()`** on every real change (`memory/epoch.ts`) — required now that the
    shelf lives in the cached block; without it a mid-turn `save_skill` leaves the memoized
    `TurnState.systemBlock` stale for the rest of that turn (`runTurn.ts:194-196, 335-347`).
  - Writes the `source` column; preserves `created_ms` (existing behavior).
- `markUsed(name, nowMs)`: `used_count += 1`, `last_used_ms = nowMs`. **Deliberately NO epoch
  bump and NO audit** — counts are never rendered in the shelf, so usage must not thrash the
  prompt cache. (Wired to `recall_skill` in v0.32.1; the store function lands here.)
- `deprecateSkill(name, nowMs, source)` / `restoreSkill(name, nowMs)`: audit-first flips of
  `deprecated_ms`; both bump the epoch (the shelf changes). `restoreSkill` also supports
  restoring the previous body/description from the latest audit row (`steps=1` semantics like
  `restoreEvolving`).
- `listShelf(cap)`: **active rows only** (`deprecated_ms = 0`); when count ≤ cap → all rows
  **ORDER BY name ASC**; when count > cap → keep the top-cap by
  (`used_count DESC, last_used_ms DESC, name ASC`) then render that subset name-ordered.
  Deterministic for fixed data; byte-stable across turns while usage doesn't cross the eviction
  boundary (and with ≤cap skills, always stable).
- `searchSkills`/`listSkills` gain an `includeDeprecated = false` default so deprecated skills
  vanish from recall too.

### `packages/server/src/skills/renderShelf.ts` (NEW)

`renderSkillShelf(): string` — deterministic, timestamp-free (the cache invariant, same contract
as `renderSoulBlock`/`renderDiaryDigest`):

```
## Things you know how to do (your skill shelf)

- <name> — <description>
- ...

(Before redoing one of these, recall_skill fetches the full procedure.)
```

- Empty library (or all deprecated) → **empty string** → the block is omitted (the
  `renderDiaryDigest` pattern at `runTurn.ts:176-178`).
- Cap: `LUNA_SKILL_SHELF_MAX` (default **20**) via `listShelf(cap)`.
- Never render counts, timestamps, provenance, or the body.

### `packages/server/src/turn/runTurn.ts` — buildSystemPrompt

- `isSkillsMode(registry: ToolRegistry): boolean` = `registry.recall_skill !== undefined`,
  beside `isCodeWriteMode`/`isShellMode`/`isRepoMapMode` (`registry.ts:239-249`). Mount truth
  comes from **registry contents, never env** (the v0.27.5 rule).

### `packages/server/src/persona/l1Contract.ts` — SKILLS_CLAUSE

- New module const, pushed after `REPO_MAP_CLAUSE` (`l1Contract.ts:124-130`); signature gains
  the **8th positional param** `skillsMounted = false`; the memo key extends to 8 segments
  (`l1Contract.ts:87-90`). ⚠ Positional-boolean hazard: update the key, both call sites, and
  every test in the same change.
- Clause content (two disciplines, mirroring the recall/remember clause shape):
  - **Use-before-redo**: before doing something that feels like a procedure you've done before,
    glance at your skill shelf; if one matches, `recall_skill` the full procedure before acting.
  - **When-to-save**: when you've just completed a reusable *procedure* — a how-to you'd want
    next time, not a one-off fact (facts are `remember`'s job) — save it with `save_skill`, and
    write the description as *what it does + when to use it*.

### `packages/server/src/tools/builtin/save_skill.ts` — description rework (prompt-only)

- Tool description rewritten to carry the when-to-use ("pushy", third person — the Anthropic

  `remember`), and that `description` must say *what + when* because the shelf displays it and
  recall matches on it. Input field `.describe()`s updated to match. No schema shape change.

## Tests

- **Migration**: `0018` applies on a DB carrying a pre-existing `0009` skill row; the row
  survives with backfilled defaults (`used_count=0, source='saved', deprecated_ms=0`);
  `skills_audit` exists; re-migration is idempotent.
- **Store** (mirror `soulStore.test.ts`): fresh insert → no audit row; update → audit row carries
  the FULL prior state; byte-identical save → no write/audit/epoch; real change → exactly one
  epoch bump; `deprecateSkill` hides from `listShelf`/`searchSkills` and bumps epoch;
  `restoreSkill` brings it back (and can restore prior body via audit).
- **Shelf render**: name-ordered; empty library → `''`; >cap library keeps top-used then renders
  name-ordered; output contains no digits-only timestamp artifacts (regex guard); two calls on
  unchanged data are `===`.
- **buildSystemPrompt**: shelf present iff `skillsMounted && LUNA_SKILL_SHELF !== '0' &&
  LUNA_MEMORY_INJECT !== '0'`; byte-identical across two consecutive builds with no writes
  (cache invariant); a `saveSkill` between builds changes it exactly once (epoch path, the
  persona.test.ts "flows into the system prompt exactly once" pattern).
- **L1**: `renderL1Contract(...)` contains the skills clause iff the 8th flag is true; memo-key
  collision test (flag-only permutations yield distinct outputs); `isSkillsMode` true iff
  `recall_skill` mounted.
- **Settings**: `skills.enabled` appears in `settingsState()` with source/env/default semantics.
- Full `bun test` green; `tsc` clean (`server` + `protocol` + `web`).

## Risk

- **Cached-block byte churn**: the shelf reshuffling would bust the Anthropic prefix cache every
  turn. Mitigated by name-ordering, no timestamps/counts, the no-op guard, and the
  byte-identity tests. (`listSkills`' `verified_ms DESC` ordering is exactly what NOT to render.)
- **Positional-boolean misthreading** silently swaps L1 clauses — the memo-key + call-site +
  test sweep is a single-change requirement.
- **Migration on the live DB**: additive ALTERs + a new table only; the soul-retire backup
  discipline (take a `.bak` before restarting onto 0018) applies operationally.
