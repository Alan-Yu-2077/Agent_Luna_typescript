# v0.32.3 — Flip distillation on + the owner surface + LD #12 amendment (close)

> **Status: PLANNED.** Initiative: Skills as Procedural Memory (Order 23, version 4/4). Risk:
> **Medium** (a live behavior flip + new dev-gated write routes). Depends: v0.32.2 **and the
> recorded live dream A/B** (the owner has eyeballed at least one real distillation on a DB
> copy). Flag: flips `LUNA_DREAM_SKILLS` default **ON** (`=0` escape hatch stays).

## Goal

Close the initiative. Distillation becomes the default (the A/B-proven behavior, escape hatch
kept), the owner gets a first-class window — a Skills panel in `/_workspace` (view / edit /
deprecate / restore, the v0.31.0 soul-editor pattern) plus panel toggles — and the design lands
in the record: LD #12 is amended to name the skill library as the injected procedural-memory
layer. After this version the loop is closed at both ends (trigger + surface + distill + prune)
and observable end-to-end.

## What ships

### The flip

- `LUNA_DREAM_SKILLS` default ON: the step's gate becomes `!== '0'` (call-time read, so no
  restart needed — the v0.32.2 note). The dark-launch tests flip polarity (the v0.24.1/v0.30.3
  pattern: flag-off tests become escape-hatch tests).
- Settings: append `{ key: 'skills.dream_distill', env: 'LUNA_DREAM_SKILLS',
  category: 'Memory', kind: 'boolean', defaultValue: '1', restartRequired: false }` — the owner
  can flip distillation live from the panel (`settings/registry.ts` SETTING_SPECS; the
  `defaultValue` must mirror the read-site default, the registry's own rule).

### `/_workspace` Skills panel (the v0.31.0 soul-editor pattern, `workspace/workspace.ts` + `index.html`)

- `GET /_workspace/api/skills` — open read (like `/api/all` + `/api/soul`): active + deprecated
  skills with all lifecycle fields (`used_count`, `last_used_ms`, `source`, `deprecated_ms`,
  `verified_ms`) + the last N `skills_audit` rows per skill + `writable` (the
  `LUNA_DEV_TOOLS === '1'` flag).
- `POST /_workspace/api/skills` (dev-tools-gated like reset/edit/soul): actions
  `save` (name/description/body → `saveSkill(..., 'owner')`), `deprecate`, `restore` — all
  through the audited store, all epoch-bumping via the store (never raw SQL).
- Panel UI: a sidebar "Skills" entry beside "Soul"; list view (name, description, provenance
  badge `saved/dream/owner`, usage count, deprecated strike-through); detail editor
  (description + body textareas, Save / Deprecate / Restore buttons); read-only with the
  dev-tools hint when locked — all the exact soul-panel interaction grammar.
- Raw-grid safety net: `/_workspace/api/edit` cell edits/deletes on the `skills` table bump the
  memory epoch (the `workspace.ts` soul-table precedent) so a raw edit also lands live.

## Tests

- **Flip polarity**: default (env unset) → the step runs; `LUNA_DREAM_SKILLS=0` → skipped (the
  escape hatch); the settings spec mirrors the read-site default.
- **Routes**: GET open (not 403 without dev tools); POST 403 without `LUNA_DEV_TOOLS=1`;
  with it — `save` writes through the audited store (audit row, `source='owner'`, epoch bump),
  `deprecate`/`restore` round-trip; a raw `/api/edit` on `skills` bumps the epoch.
- **Panel contract**: the GET payload carries lifecycle fields + audit tails + `writable`;
  deprecated skills flagged, not hidden (the owner sees the whole library).
- **No dangling**: grep/tsc confirm no leftover dark-launch-only branches; the initiative's
  README acceptance boxes all check.
- Full `bun test` green; `tsc` clean ×3 (server + protocol + web untouched-but-verified).

## What this version explicitly does NOT include

- Skill composition / auto-expansion of skill references — documented as a plain-text
  convention only ("a body may name another skill"); any mechanism belongs to the future
  code-capability initiative.
- Embedding skill **bodies** into recall (name+description stays the key — revisit on lived
  evidence).
- Any change to the shelf's render shape or the L1 clause wording (stable since v0.32.0 unless
  the A/B says otherwise — record deviations in DEVELOPMENT.md).

## Risk

- **The flip is a live behavior change** — mitigated by the A/B gate being a hard dependency,
  the call-time escape hatch, per-cycle caps, and one-call restore. Exactly the v0.30.3 risk
  shape.
- **New write routes** — dev-tools-gated like every mutating workspace route; writes go through
  the audited store only, so the panel cannot create un-audited state.
- **Panel drift vs store invariants** — the POST handler reuses store functions rather than SQL,
  so no-op guards + epoch discipline hold by construction.
