# v0.30.3 — Flip default, retire `core_memory`, close the initiative

> **Status: ✅ SHIPPED 2026-07-04** (branch `feat/soul-file-v0.30.1-3`; the live dream A/B is the
> owner's pre-merge operational check). Initiative: The Soul File (Order 22, version 4/4). Risk:
> **Medium**. Depends: v0.30.2. Flag: removes `LUNA_SOUL_DB`.

## Goal

Make the soul the only path. Flip `LUNA_SOUL_DB` on, delete the file+`core_memory` persona path, drop
the retired tables via a migration, and land the LD #12 amendment in `REWRITE_CONTEXT.md`. After this
version the persona is a single DB-stored soul file with a fixed core (git-seeded) and a
Luna-evolving section, and `core_memory` is gone.

## What ships

**Remove the flag + the old path**
- `packages/server/src/turn/runTurn.ts` — `buildSystemPrompt` always renders `renderSoulBlock()`; the
  `loadPersona()` persona-file push and the `LUNA_SOUL_DB` branch are deleted. `renderCoreBlock()` now
  unconditionally emits **only** the L3 `## Long-term memory` section.
- `packages/server/src/memory/renderCoreBlock.ts` — drop the self/relationship rendering entirely (it
  moved to `renderSoul.ts`); the function is now L3-only. Consider renaming to `renderL3Block` for
  honesty (optional; a rename touches call sites + tests).
- `packages/server/src/dream/cycle.ts` — `persona_update` unconditionally writes the soul; the
  `core_memory`/`updateCore` branch is deleted.
- `packages/server/src/persona/loader.ts` — `loadPersona()` is now **seed-only** (read by
  `seedSoulOnBoot`), no longer a runtime source. Keep it (the fixed core still seeds from the file);
  its mtime cache is fine for the boot read.

**Retire the tables** — `packages/server/src/migrations/0017_retire_core_memory.sql`:
- Safety re-migrate: if a `core_memory` row exists and the soul's `evolving_*` are still empty (a DB that
  somehow reached here unseeded), copy it over first. Then `DROP TABLE core_memory; DROP TABLE
  core_memory_audit;`. (Never edit 0007/0016; this is a new forward migration.)

**Deprecate the protocol type** — `packages/protocol/src/memory.ts`: remove `CoreMemory` (or mark
deprecated if any external reader remains — verify none: grep shows only server-internal use). `Soul`
is now the type.

**Retire `coreMemory.ts`** — delete `getCore`/`updateCore`/`restore` (superseded by `soulStore`).
Verify no remaining importers (`renderCoreBlock`, `cycle`, `remember` tool, tests) — repoint the
`remember`-tool "update your sense of self/relationship" path (renderCoreBlock.ts's closing hint +
its dispatcher) to `updateEvolving`.

**Land the LD amendment** — `docs/REWRITE_CONTEXT.md`: amend LD #12's "prose core memory" clause to
record that the prose core memory is now the DB soul file's evolving section, `core_memory` retired,
persona moved file→DB (file = seed). Per the luna-ts-dev Phase-4 rule, this is where the amendment lands.

## Tests

- **Single path**: with no `LUNA_SOUL_DB` in the env, the system block renders the soul + L3-only core
  block; the persona-file text is not read at runtime (only at seed).
- **Migration drops cleanly**: `0017` applies on a DB with data (re-migrates if needed, then drops);
  `core_memory`/`core_memory_audit` no longer exist; `soul` intact.
- **No dangling refs**: a grep test (or tsc) confirms zero importers of `coreMemory.ts` / `CoreMemory`
  / `LUNA_SOUL_DB` remain.
- **`remember` tool self/relationship path** writes the soul's evolving section, not a dropped table.
- Full `bun test` green; `tsc` clean across `packages/protocol` + `packages/server`.

## What this version explicitly does NOT include

- Folding embodiment / humanity / L1 contract into the soul (initiative-wide non-goal — a possible
  future initiative once the soul substrate is proven).
- Any change to L3, diaries, or the dream steps other than `persona_update`.
- A dev editing UI for the fixed core beyond the file-seed sync.

## Risk

- **Irreversible table drop** — mitigated by the safety re-migrate in `0017` (copies any stray
  `core_memory` into the soul before dropping) and by the fact that v0.30.0–v0.30.2 already migrated +
  proved the soul on the live instance. Take a DB backup before the drop migration runs on the real DB
  (operational note, not code).
- **Missed importer** — a leftover `getCore()`/`CoreMemory` reference would break at tsc; the grep/tsc
  test is the guard. Sweep `remember` tool + traces + workspace views.
- **Default flip is a live behavior change** — but it has been A/B-validated across v0.30.1–v0.30.2, so
  the flip only removes the escape hatch, it does not introduce new behavior.
