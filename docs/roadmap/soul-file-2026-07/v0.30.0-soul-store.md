# v0.30.0 — Soul store + migration + seed (dark launch)

> **Status: SHIPPED (2026-07-04, branch `feat/soul-file-v0.30.0`, draft PR pending review).**
> Initiative: The Soul File (Order 22, version 1/4). Risk: **Medium**.
> Depends: Initiative 21 (shipped). Flag: `LUNA_SOUL_DB` (default **off** — the table is populated
> but nothing reads it this version).

## Goal

Land the DB substrate with **zero runtime behavior change**. Create the `soul` table, a `soulStore`
module, and a boot-time seed that (a) loads the **fixed core** from a restructured `persona/default.md`
(hash-gated) and (b) migrates the current `core_memory` row into the **evolving section**. Nothing
reads the soul yet — `buildSystemPrompt` still uses `loadPersona()` (file) + `renderCoreBlock()`
(core_memory). This isolates the riskiest, hardest-to-reverse piece — schema + migration + seed sync —
behind a dark launch so it can be proven in isolation before any prompt byte moves.

## What ships

**`packages/server/src/migrations/0016_soul.sql`** (new; never edit a shipped migration)
- `CREATE TABLE soul (id INTEGER PRIMARY KEY CHECK (id = 1), fixed_text TEXT NOT NULL, fixed_hash TEXT
  NOT NULL, evolving_self TEXT NOT NULL DEFAULT '', evolving_bond TEXT NOT NULL DEFAULT '', updated_ms
  INTEGER NOT NULL)`.
- `CREATE TABLE soul_audit (id INTEGER PRIMARY KEY AUTOINCREMENT, t_ms INTEGER NOT NULL, prev_self
  TEXT NOT NULL, prev_bond TEXT NOT NULL, source TEXT NOT NULL)` — mirrors `core_memory_audit` so the
  evolving section keeps audit + `restore(n)`.
- `core_memory` / `core_memory_audit` are **left intact** (retired only in v0.30.3).

**`packages/protocol/src/memory.ts`** — add a `Soul` zod type `{ fixed_text, evolving_self,
evolving_bond, updated_ms }`. `CoreMemory` stays (deprecated at v0.30.3).

**`packages/server/persona/default.md`** — restructure IN PLACE into the fixed-core sections (Identity
core / Personality / Background / Cognitive style / Language & voice — see the initiative README's
target structure). **Content-preserving**: the words are today's `default.md`, only re-sectioned. This
file is now the *seed*, not the runtime source. (It still IS the runtime source this version — the swap
is v0.30.1 — so the restructure must remain a faithful persona so v0.30.0 stays byte-safe once loaded.)

**`packages/server/src/memory/soulStore.ts`** (new)
- `getSoul(): Soul` — reads row id=1 (mirrors `getCore`), `EMPTY` fallback.
- `seedFixedCore(fixedText: string): void` — hash the text (`content_hash` util already in the repo,
  memory/… — reuse it); if the stored `fixed_hash` matches, **no-op** (no write, no epoch bump — the
  cache invariant). Else upsert `fixed_text`/`fixed_hash`, **preserving** `evolving_*`. First-ever call
  inserts the row.
- `updateEvolving(patch: {self?: string; bond?: string}, source: string): Soul | null` — audit-first
  into `soul_audit`, **no-op guard** (both fields byte-identical → skip), `bumpMemoryEpoch()` on a real
  change. Straight port of `coreMemory.updateCore`'s three load-bearing properties.
- `restoreEvolving(steps = 1)` — port of `coreMemory.restore` over `soul_audit`.

**`packages/server/src/memory/soulSeed.ts`** (new) — `seedSoulOnBoot()`:
1. `seedFixedCore(loadPersona().text)` — the fixed core, hash-gated (no-op when unchanged).
2. **One-time migration** of the evolving section: if `soul.updated_ms === 0` (never seeded) AND a
   `core_memory` row exists, copy `self_state → evolving_self`, `relationship_status → evolving_bond`
   **verbatim** (NO cleaning — that is v0.30.2), via a direct write (not `updateEvolving`, to avoid a
   spurious audit row for the migration). Idempotent: guarded on the never-seeded check.
- Called from the server boot path (where `preloadSessions()` / migrations run — packages/server/src/main.ts),
  after `migrate()`.

**No change to `runTurn.ts`, `loader.ts`, `renderCoreBlock.ts`, or `cycle.ts` this version.** The soul
table is written and readable but unused by the prompt.

## Tests (`packages/server/src/memory/soulStore.test.ts` + `soulSeed.test.ts`)

- **Migration applies**: `migrate(db, dir)` creates `soul` + `soul_audit`; `getSoul()` returns EMPTY on
  a fresh db.
- **Seed is hash-gated**: `seedFixedCore(t)` twice with the same text → exactly one write (second is a
  no-op: `updated_ms` unchanged, no epoch bump). Different text → a second write.
- **Seed preserves evolving**: set `evolving_self`/`bond`, then `seedFixedCore(newFixed)` → fixed
  changes, evolving is untouched.
- **updateEvolving parity**: audit-first (a `soul_audit` row written with prev state); byte-identical
  patch → no-op (no audit row, no epoch bump); a real change bumps the epoch once. `restoreEvolving(1)`
  walks back one step.
- **Boot migration**: with a populated `core_memory` and an unseeded `soul`, `seedSoulOnBoot()` copies
  self/relationship verbatim into `evolving_self/bond`; a second call is a no-op (idempotent).
- Full `bun test` green; `tsc` clean across `packages/protocol` + `packages/server`.

## What this version explicitly does NOT include

- **Any prompt/injection change** — `buildSystemPrompt` is untouched; `loadPersona()` (file) +
  `renderCoreBlock()` (core_memory) still drive the persona. → v0.30.1.
- **Any dream change** — `persona_update` still writes `core_memory`. → v0.30.2.
- **Any cleaning** of the migrated `relationship_status` — copied verbatim. → v0.30.2.
- **Retiring `core_memory`** — the table stays live and authoritative this version. → v0.30.3.
- Folding embodiment / humanity / L1 contract into the soul — out of the whole initiative.

## Risk

- **Migration is hard to reverse** — mitigated by the dark launch: even if the soul table is wrong,
  nothing reads it, so runtime behavior is provably unchanged (the acceptance test asserts the rendered
  system block is byte-identical to pre-v0.30.0). `core_memory` remains the source of truth.
- **Cache-invariant regression** — the hash-gated seed must be a true no-op on an unchanged file;
  tested explicitly (no epoch bump on a repeat seed).
- **Boot ordering** — `seedSoulOnBoot()` must run after `migrate()` and be safe when no `core_memory`
  row exists (fresh install) → seeds an empty evolving section, fine.

## Acceptance criteria

- [ ] `0016_soul.sql` applies; `soul` + `soul_audit` exist; `core_memory` untouched.
- [ ] `soulStore` (get / seedFixedCore / updateEvolving / restoreEvolving) with the audit + no-op +

- [ ] `seedSoulOnBoot()` seeds the fixed core hash-gated + migrates core_memory → evolving verbatim,

- [ ] Rendered system block is **byte-identical** to pre-v0.30.0 (dark launch proof). Tests green, tsc clean.
