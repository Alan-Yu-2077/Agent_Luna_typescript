# v0.30.1 — Render the soul into the prompt

> **Status: PLANNED.** Initiative: The Soul File (Order 22, version 2/4). Risk: **Medium**.
> Depends: v0.30.0. Flag: `LUNA_SOUL_DB` (default **off**; `=1` renders from the soul table — A/B).

## Goal

Swap the injection source. When `LUNA_SOUL_DB=1`, `buildSystemPrompt`'s persona block (04) renders the
**whole soul** — fixed core + a fenced evolving section — from the DB, and the separate core-memory
self/relationship block (07) is gone (its **L3 fact list survives**, rendered on its own). Default off
keeps today's file+`core_memory` path byte-for-byte, so the two are A/B-comparable on one running
instance. No dream change yet — the evolving section still shows the migrated (uncleaned) prose.

## What ships

**`packages/server/src/memory/renderSoul.ts`** (new) — `renderSoulBlock(): string`, the DB-sourced
replacement for the persona-file block:
- `getSoul()` → emit `fixed_text`, then, when either evolving field is non-empty, a fenced sub-section:
  `## Who I am becoming` (evolving_self) + `## The bond, right now` (evolving_bond). First-person prose,
  same headings the evolving section will keep.
- **Deterministic + timestamp-free** (the cache invariant). Empty soul → `FALLBACK_PERSONA` (reuse
  loader's constant so the degrade path is identical to today).

**`packages/server/src/memory/renderCoreBlock.ts`** — split the self/relationship half out. Behind the
flag: when `LUNA_SOUL_DB=1`, `renderCoreBlock()` emits **only** the `## Long-term memory` (L3) section —
the `## About yourself` / `## Your relationship` prose is now the soul's job. Off: unchanged. (Keep the
function name; the L3 render is load-bearing and untouched.)

**`packages/server/src/turn/runTurn.ts`** — in `buildSystemPrompt` (runTurn.ts:159-171):
- When `LUNA_SOUL_DB=1`: replace the `loadPersona()` persona push (runTurn.ts:160-165) with
  `renderSoulBlock()` (keeping the same "This is who you are…" framing line), and rely on the flagged
  `renderCoreBlock()` above to drop the self/relationship half. `EMBODIMENT_BLOCK` + `renderHumanityBlock()`
  stay exactly where they are (between soul and memory). Off: the existing path, unchanged.
- The one-time byte change (persona now includes the evolving prose inline, core block loses it) busts
  the prompt cache exactly once on flag flip — acceptable and expected.

**`packages/server/src/persona/loader.ts`** — unchanged this version (still the seed source; the boot
sync in v0.30.0 already feeds the soul). `loadPersona()` stays for the off path + as the seed reader.

## Tests (`renderSoul.test.ts` + `runTurn` system-block tests)

- **Soul render shape**: `renderSoulBlock()` emits `fixed_text` then the two evolving sub-sections when
  populated; omits the evolving fence when both are empty; falls back to `FALLBACK_PERSONA` on an empty
  soul.
- **Determinism**: two calls with no write between them return byte-identical strings (no timestamp leak).
- **Flag A/B**: with `LUNA_SOUL_DB=0` the assembled system block equals the v0.29.x baseline
  (persona-file + full core block). With `=1`, the block contains the soul's fixed+evolving prose once,
  and the core block contains **only** the L3 list (no duplicate self/relationship).
- **No self/relationship duplication**: assert the self_state text appears exactly once in the whole
  system block under `=1` (in the soul, not also in the core block).
- **Epoch/caching**: an `updateEvolving()` write bumps the memory epoch so the memoized system block
  (`TurnState.systemBlock` / `systemBlockEpoch`, runTurn.ts:189-194) re-renders; no write → same bytes.
- Full `bun test` green; `tsc` clean.

## What this version explicitly does NOT include

- **Any dream change** — `persona_update` still writes `core_memory` (which, under `=1`, is no longer
  rendered — so a dream write is dark until v0.30.2 rewires it to the soul). → v0.30.2.
- **Cleaning the evolving prose** — the migrated `relationship_status` ledger still shows. → v0.30.2.
- **Retiring `core_memory` / removing the off path / flipping the default** → v0.30.3.

## Risk

- **Double-render / drift** — the split between `renderSoulBlock` (self+bond) and `renderCoreBlock`
  (L3 only) under the flag must be exact; the "self_state appears exactly once" test guards it.
- **Cache invariant** — `renderSoulBlock` must be timestamp-free and stable; the determinism test guards
  it. The one-time flip cache-bust is intended.
- **Behavioral shift on flip** — the persona now reads as one continuous document (fixed + her own
  evolving voice) rather than two blocks 60 lines apart. This is the *point*, but it is a real prompt
  change → validate with a live A/B turn before v0.30.3 flips the default.

## Acceptance criteria

- [ ] Under `LUNA_SOUL_DB=1`, block 04 renders the full soul from the DB and the self/relationship
      prose no longer appears in the core block; L3 facts still inject.
- [ ] Under `LUNA_SOUL_DB=0`, the system block is byte-identical to v0.29.x.
- [ ] `renderSoulBlock` is deterministic; a soul write bumps the epoch exactly once; the memoized
      system block re-renders on that bump only.
- [ ] Tests green; tsc clean.
