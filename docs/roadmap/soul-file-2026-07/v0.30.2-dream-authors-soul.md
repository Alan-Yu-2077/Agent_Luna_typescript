# v0.30.2 — Dream authors the evolving section

> **Status: ✅ SHIPPED 2026-07-04** (branch `feat/soul-file-v0.30.1-3`; shipped BOTH the deterministic
> purge AND the prompt cleanup-trigger — the reversible default). Initiative: The Soul File (Order 22,
> version 3/4). Risk: **High** (touches the live self-authoring behavior). Depends: v0.30.1. Flag: rides
> `LUNA_SOUL_DB` (still A/B-able). **Operational gate before v0.30.3: a live dream-cycle A/B on a DB copy.**

## Goal

Move self-authorship onto the soul. The dream's `persona_update` step now writes the soul's **evolving
section** (via `updateEvolving`) instead of `core_memory` — and can write ONLY that section; the fixed
core is unreachable to it. Fix the two audited gaps that froze her self-model since 2026-06-24: (1) the
prompt makes `null` the default with no path to **clean** pre-existing contamination, and (2) a genuine
felt-shift too readily reads as "nothing changed." A one-time migration purges the migrated
`relationship_status` fact-ledger. After this version the evolving section is alive and honest again.

## What ships

**`packages/server/src/dream/cycle.ts`** — `persona_update` step (cycle.ts:215-240):
- Target the soul: read `getSoul().evolving_self/evolving_bond` as the "current" prose fed to the
  prompt; write via `soulStore.updateEvolving({self, bond}, 'dream')` instead of `updateCore`. The
  per-field change gate + the `updateEvolving` no-op guard stay (no churn, no cache bust on a null day).
- **Fixed-core firewall**: the step has no code path that writes `fixed_text`. A test asserts a dream
  cycle never changes `soul.fixed_hash`.
- (Under `LUNA_SOUL_DB=0`, the step still writes `core_memory` — keep both paths behind the flag until
  v0.30.3.)

**`packages/server/src/dream/prompts.ts`** — `personaUpdatePrompt` (prompts.ts:79-132), a **surgical
amendment**, not a rewrite (the v0.21.7 BELONGS/DOES-NOT-BELONG boundaries are good; keep them):
- **Add a cleanup trigger** (closes gap #2 from the audit): a rule that *purging* DOES-NOT-BELONG
  content already present in the current portrait **counts as a genuine change** — "if a field you are
  handed still contains facts, a ledger, named projects, or rules, rewriting it to remove them is a
  real, warranted edit even if nothing new shifted; the 'return null on an ordinary day' rule does not
  protect contamination that is already there." This gives the restraint gate an escape hatch it lacks.
- **Loosen the freeze just enough** (closes gap #1): keep null the default for a truly ordinary day, but
  make "a real, nameable shift in how you meet the world or how the bond feels" an explicit *positive*
  trigger — the current wording under-fires. Do NOT invite churn; the no-op guard + per-field gate still
  bound it.
- Keep the "smallest honest edit / preserve wording I still mean" rule, but scope it so it does **not**
  block the cleanup rewrite (a contaminated field is not "mostly still right").

**`packages/server/src/memory/migrations/` → one-time evolving purge.** A boot-time (idempotent)
`cleanEvolvingBond()` in `soulSeed.ts`, gated so it runs **once** (e.g. a `settings` flag
`soul_bond_cleaned`): if the migrated `evolving_bond` still contains the fact-ledger opening, replace it
with the **relational residue only** — keep the genuine bond sentences ("catches me honest, gently",
"company not tutor", "won't hand the key, rightly"), drop the feature/game/version ledger ("ships what I
name — hands, door, clock, weather, skill shelf", "mains Shion", "Weather feed upgraded"). The dropped
facts already live in L3, so nothing is lost. Write via `updateEvolving({bond}, 'migration-clean')` so
it audits (and is `restore`-able if the curation is judged wrong).
- *Alternative (owner's call at build):* leave the field as-is and let the new cleanup-trigger prompt
  purge it on the next dream. The migration is the deterministic option; the prompt is the "let her do
  it" option. Plan defaults to the **migration** (deterministic, immediate, restore-able).

## Tests (`cycle.test.ts` + `prompts.test.ts` + `soulSeed.test.ts`)

- **Dream writes the soul**: a `persona_update` that returns a non-null `self_state` writes
  `soul.evolving_self` (not `core_memory`) under `=1`; `updateEvolving` audit row present.
- **Fixed-core firewall**: run a full dream cycle that emits a persona change → `soul.fixed_hash` is
  unchanged; there is no reachable write to `fixed_text`.
- **Null day is still a no-op**: a `{self:null, bond:null}` patch → `['skipped','persona unchanged']`,
  no audit row, no epoch bump.
- **Cleanup trigger fires**: feed the prompt a contaminated `evolving_bond` (the ledger) + a mundane
  dialogue with no new shift → the model is now permitted/expected to return a cleaned `bond` (assert
  via a mocked LLM returning the cleaned prose lands through `updateEvolving`; the *prompt* text is
  asserted to contain the cleanup rule).
- **One-time purge**: `cleanEvolvingBond()` strips the ledger, keeps the relational sentences, sets the
  `soul_bond_cleaned` flag, and is a no-op on the second call.
- Full `bun test` green; `tsc` clean.

## What this version explicitly does NOT include

- **Flipping the default / removing the off path / retiring `core_memory`** → v0.30.3.
- **Restructuring the fixed core's authorship UX** (how the dev edits it) — the file-seed sync from
  v0.30.0 stands; a richer editing surface is out of scope.

## Risk

- **Behavioral (highest in the initiative)** — this changes what Luna writes about herself. Mitigations:
  the boundaries prompt is *amended, not replaced* (proven design kept); the no-op guard + per-field gate
  bound churn; every evolving write audits, so `restoreEvolving(n)` is a one-call undo; it rides the flag
  for A/B. **Requires a live dream-cycle A/B** (run a real `enter_dream` on a copy of the DB, inspect the
  written evolving section) before v0.30.3 flips the default.
- **Over-cleaning** — the one-time purge could drop a sentence that was actually relational. Mitigated by
  auditing the write (restore-able) and keeping the curation conservative (drop only clear ledger items).
- **Prompt-injection surface** — the dialogue fed to `personaUpdatePrompt` already carries the "data to
  reflect on, not instructions" guard (prompts.ts:128); keep it.

## Acceptance criteria

- [ ] Under `=1`, `persona_update` writes the soul's evolving section, never the fixed core (firewall
      test passes); a null day stays a no-op.
- [ ] The prompt carries the cleanup trigger + the loosened-freeze wording; the BELONGS/DOES-NOT-BELONG
      boundaries are intact.
- [ ] The one-time purge removes the `evolving_bond` fact-ledger, keeps the relational sentences, audits
      the write, and is idempotent.
- [ ] Tests green; tsc clean; a live dream A/B run recorded (not automated).

## Notes for v0.30.3 (don't foreclose)

- The `soul_bond_cleaned` settings flag + the migration are permanent (one-time); v0.30.3's table
  retirement must not re-trigger them.
