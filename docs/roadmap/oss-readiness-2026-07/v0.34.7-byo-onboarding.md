# v0.34.7 — New-user onboarding (BYO Live2D model + optional BYO voice)

> **Status: PLANNED.** Initiative: OSS Readiness (Order 8, version 8/9). Risk: **High** — net-new
> desktop plumbing (preload injection, model-folder picker, userData model serving) + a first-run voice
> default flip. Depends: v0.34.6 (assets gone + graceful empty state), v0.34.5 (docs), v0.34.2 (neutral
> endpoints). Flag: `LUNA_TTS_BACKEND` (voice default flips to text-only, quick-revert).

## Goal
Turn the "no bundled model/voice" state from v0.34.6 into a **guided path**: a friendly empty state, a
way to install a Live2D model (drop-in on web; folder-picker on desktop), a zero-setup browser voice,
and clear docs pointing at real free resources. This is the feature that makes "clone → running" true
for a stranger.

## What ships — model
- **Resolve the model URL** — replace the `pixiLive2DSink.ts:90` literal with `resolveModelUrl()`:
  `localStorage 'luna:model-url'` → `window.lunaConfig?.modelUrl` (desktop preload injects
  `LUNA_MODEL_URL`) → **undefined** (NO yumi fallback; undefined short-circuits to the empty state — no
  404 spam).
- **Empty state** — turn `layout.ts:180-183` into a friendly card keyed by `app.ts` `dataset.modelState`
  (`none` / `webgl-off` / `load-failed`): neutral glyph, "No avatar installed", a line pointing at the
  drop location + `docs/SETUP.md`.
- **Desktop BYO** — a `userData/models` dir (`main.ts` `resolvePaths`/`ensureUserConfig`); teach
  `serve.ts` `startWebHost` to resolve `/models/*` against `userModelsDir` **before** `webDist` (with a
  per-root traversal guard); a "Choose model folder…" picker IPC (`dialog.showOpenDialog`) that copies
  the folder + writes `LUNA_MODEL_URL`. **Preload must inject `window.lunaConfig.modelUrl`** — heed the
  v0.27.2 `app.getAppPath()` preload-path lesson so the bridge actually loads.

## What ships — voice
- **Zero-setup default** — ship a **Web Speech API** sink (browser TTS) so a fresh install has a voice
  with no backend. **Flip the voice default to text-only/browser** (`luna:tts` unset → OFF for the http
  backend; `app.ts:56/99`, `layout.ts:115`) behind `LUNA_TTS_BACKEND` (`none|browser|http`) — a boot
  parser must actually read it to pick the sink (today it only gates on `luna:tts !== '0'`).
- **BYO GPT-SoVITS via DIRECT api_v2 — no owner glue (owner-confirmed 2026-07-09).** The private glue
  (`gpt-sovits-service.js` + `gpt-sovits-manager.js`, ~400 lines, spawns the Python backend + holds the
  `neoru` reference audio) is **NOT vendored** — a public clone must not depend on private files. Instead:
  - **The user runs GPT-SoVITS themselves** and Luna talks to **its own `api_v2` HTTP server** (`/tts`).
    Ship **`services/tts/docker-compose.yml`** (community GPT-SoVITS `api_v2` image, weights fetched at
    runtime, never committed) + a `.env`-driven config; the user supplies their **own voice** (ref audio
    + model), `neoru` excluded.
  - **Rewrite the forward to translate `{text, voice}` → api_v2 `/tts` directly** (text/text_lang/
    ref_audio_path/prompt params — the minimal translation the old glue did), at `LUNA_TTS_URL` (default
    the compose port). Fold it into the existing `packages/web/dev-server.ts` + `packages/desktop/src/
    serve.ts` proxy and **drop the owner-glue `require`** — either delete `scripts/tts-proxy.cjs` or
    reduce it to that thin api_v2 forwarder. (This is the self-contained path the cancelled Init 7
    already sketched: "dev-server translates {text,voice}→api_v2, drop the Python Node proxy".)
  - `bootGate.ts:22` reworded (drop "~5GB"); the download gate only mounts for the GPT-SoVITS backend.
- **Rename** `/api/gpt-sovits` → `/api/tts` + `LUNA_TTS_PROXY` → `LUNA_TTS_URL` — touch `ttsClient.ts:10`,
  `dev-server.ts:23`, `serve.ts:31/42`, the forwarder, **and** `ttsClient.test.ts` + `serve.test.ts`
  atomically (keep the SSRF/traversal guard describe) or forwarding 404s.
