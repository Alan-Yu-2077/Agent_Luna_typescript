# v0.34.3 — Portable paths (de-hardcode homebrew / absolute paths)

> **Status: PLANNED.** Initiative: OSS Readiness (Order 4, version 4/9). Risk: **Medium** (the
> vecRuntime change is the one real bug; signature unchanged so callers are untouched). Depends: v0.34.0.
> Flag: none.

## Goal
Make the repo run correctly off the owner's exact machine. Fixes one **real functional bug** (semantic
recall silently dead on non-homebrew envs) plus absolute-path leaks.

## What ships
- **REAL BUG — `packages/server/src/memory/recall/vecRuntime.ts:5` (also `:15/:17`)** hardcodes a single
  `/opt/homebrew/.../libsqlite3.dylib` with **no env override or fallback** → `existsSync` misses on
  Intel-brew / Linux / non-brew → `sqlite-vec` never loads → recall silently degrades to slow TS-cosine
  for every non-owner user. **Fix:** a multi-candidate probe + `LUNA_SQLITE_LIB` override, mirroring the
  existing pattern in `packages/desktop/src/backend.ts:47` and `packages/desktop/src/location.ts:18`:
  `[LUNA_SQLITE_LIB, /opt/homebrew/opt/sqlite/lib/…, /usr/local/opt/sqlite/lib/…, Linux .so paths]`,
  take the first that exists. Signature/return unchanged → callers (`main.ts:47`, `test-preload.ts:5`,
  soak/sweep) untouched. Apply the identical fix to `packages/server/scripts/spike-sqlite-vec.ts:7`.
- **Document** `LUNA_SQLITE_LIB` in `.env.example`.
- **`README.md:58`** — reword the private Python source path generically (the README itself is rewritten
  in v0.34.5; this is the abs-path line if touched earlier).
- **`.claude/launch.json:6/13`** `runtimeExecutable:/opt/homebrew/bin/bun` → `bun` on PATH — **or** rely
  on v0.34.5 removing `.claude/` entirely (preferred; note the cross-dependency).
