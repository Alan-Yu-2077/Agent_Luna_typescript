# v0.34.4 — Locale neutralization + weather config docs

> **Status: PLANNED.** Initiative: OSS Readiness (Order 5, version 5/9). Risk: **Low** (hint/example

## Goal
Stop the UI/config from presuming a single Shanghai-based owner, and document the weather subsystem
that a new user currently can't discover.

## What ships
- **Settings UI examples** — `packages/server/src/settings/registry.ts:50/131` Shanghai example coords
  `31.23,121.47` → neutral placeholder (`<lat>,<lon>` or a well-known non-owner city); `:141`
  `Asia/Shanghai` hint → `e.g. America/New_York`. (The `lat_lon` + `time.zone` *defaults* are already
  `''` — only the example/hint strings change.)
- **`.env.example:64`** `LUNA_TZ=Asia/Shanghai` → `UTC` / neutral.
- **Weather progress string** — `packages/server/src/tools/builtin/weather.ts:52` `'正在查天气…'`
  (Chinese-only) → English (or bilingual). **Grep `weather.test.ts` first** — if it asserts the Chinese
  string, update the test in the same version.
- **NEW `.env.example` weather config block** (the audit's F2 — a top feature is undiscoverable): add
  `LUNA_LAT_LON` (tool dormant until set), `LUNA_WEATHER_AMBIENT`, `LUNA_WEATHER_PROVIDER`
  (`open-meteo` keyless default | `qweather` keyed), `LUNA_WEATHER_API_KEY`/`_HOST`, units/TTL/timeout —
  with a **non-Shanghai** example coordinate.
