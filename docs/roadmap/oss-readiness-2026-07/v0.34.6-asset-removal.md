# v0.34.6 — Asset removal (delete yumi model + de-personalize TTS, build resilience)

> **Status: PLANNED.** Initiative: OSS Readiness (Order 7, version 7/9). Risk: **High** — a naive `rm`
> breaks `bun run build`, `bun test`, and `pack`/`smoke:packaged`. Every deletion is coupled to a fix
> that MUST land in the same commit. Depends: v0.34.0. Flag: none.

## Goal
Delete the one un-shippable bundled asset — the `yumi` Live2D model — and **de-personalize** (not
delete) the TTS integration: drop the owner-specific sibling-repo default so nothing points at private
paths, while keeping the GPT-SoVITS glue as the bring-your-own hook (the `neoru` voice weights are
never in this repo). Keep the build/test/pack green with **no bundled model and no configured voice**.
Runtime already degrades gracefully; the work is making the build graph + smoke gate agree.

## What ships — model
- **Delete** `packages/web/public/models/yumi/` (all 25 files; 13 are dormant, whole-folder delete is
  code-safe).
- **MANDATORY same-version build fix** — `packages/web/package.json:12` `build:assets`:
  `cp -R public/models dist/models` **fails once `public/models/` is empty/absent** (git drops empty
  dirs → fresh clone has no dir → non-zero exit → `bun run build` fails → cascades to desktop
  `pack`/`smoke:packaged`). Replace with resilient copy:
  `cp public/live2dcubismcore.min.js dist/ && mkdir -p dist/models && cp -R public/models/. dist/models/ 2>/dev/null || true`.
- **Ship a TRACKED keeper** `packages/web/public/models/README.md` (git won't preserve an empty dir) that
  also documents the BYO drop contract (`<name>/<name>.model3.json`). Do NOT delete the `models/` parent.
- **Smoke verdict** — `packages/desktop/src/smoke.ts:27-44` asserts `p.canvas && p.placeholderGone &&
  p.headX!==null` → always false with no model → `smoke`/`smoke:packaged` exit 1 on every OSS build.
  **Redefine:** no-model boot (`.luna-app` present + placeholder shown + WS reachable) = PASS; require
  canvas/headX only when a model manifest is present. (Aligns with v0.34.7's empty-state probe.)
- **De-name the persona** — `packages/server/src/turn/runTurn.ts:105` `EMBODIMENT_BLOCK` says
  "(the yumi avatar)" → "a visible on-screen Live2D form". (Optionally gate the whole block on a model
  being configured.)
- **Placeholder copy** — `packages/web/src/ui/layout.ts:180-183` `.model-placeholder` leaks 'yumi' +
  'real model in v0.13.1'; neutralize the copy here (the full empty-state UX is v0.34.7).

## What ships — voice (DE-PERSONALIZE, do NOT delete — owner refinement 2026-07-09)
The TTS **integration stays**; only the owner-specific coupling goes. The `neoru` voice weights are
**never in this repo** (confirmed: 0 matches — they live in the private sibling `../../Agent_Luna/TTS`),
and the actual GPT-SoVITS glue (`gpt-sovits-service.js`) is in that sibling too. So this version only
**de-personalizes** the wiring; the bring-your-own setup is built in v0.34.7.
- **KEEP** `scripts/tts-proxy.cjs`, `packages/desktop/src/tts.ts` + its test, the `dev-all.ts` TTS
  spawn, and the desktop TTS supervisor — the integration is the BYO hook.
- **Remove the owner-specific default** — `scripts/tts-proxy.cjs:16` (`process.env.LUNA_TTS_DIR ||
  path.resolve(__dirname,'..','..','Agent_Luna','TTS')`) → require `LUNA_TTS_DIR` (default **unset** →
  the existing graceful "TTS module not found — starting without voice" path at `dev-all.ts:24` /
  `tts-proxy.cjs:21` already handles absence). Scrub the "not-open-sourced / Python project" header
  comments (`tts-proxy.cjs:1-8`) to neutral "point `LUNA_TTS_DIR` at a GPT-SoVITS `api_v2` install".
- **Drop the "~5GB voice model" owner-baked strings** — `packages/web/src/ui/bootGate.ts:22,56,57,58`
  → generic "Loading the voice model…" (only shown when a voice backend is actually configured).
- **KEEP the generic forward** in `packages/web/dev-server.ts` + `packages/desktop/src/serve.ts` and
  **KEEP `serve.test.ts`'s SSRF/traversal describe** (it guards the BYO proxy).
- Text-only degrade already works via `webAudioSink.ts:82` (502/503/504 excluded from the fail latch →
  null → text keeps working). Preserve that exclusion — an absent backend must not trip the
  `mutedUntil` latch.
