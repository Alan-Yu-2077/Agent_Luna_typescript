# v0.29.0 — Silence idle-timer core

> **Status: ✅ SHIPPED 2026-07-03.** Initiative: Proactive silence-trigger redesign (Order 21,
> version 1/2). Risk: **Medium**. Depends: Initiative 17 (silence ladder, shipped). Flag:
> `LUNA_PROACTIVE_SILENCE_TIMER` (default **on**; `=0` restored the old user-only anchor — retired in v0.29.1).

## Goal

Replace the silence ladder's broken gap computation with a single **idle-timer**. Introduce one
`session.lastActivityMs`, bumped by every piece of conversation activity (user messages + every Luna
reply). The ladder and the anti-spam idle floor read `silenceGap = now - lastActivityMs` instead of
`now - lastUserMs`. This makes "silence" mean *time since the last thing said in the channel* — so
Luna stops interrupting a conversation seconds after she herself finished replying. The two other
clocks are untouched: `lastUserMs` still triggers the escalation reset, `lastProactiveMs` still
governs outreach spacing.

## What ships

**`packages/server/src/turn/session.ts`**
- Add field `lastActivityMs: number` to `Session` (session.ts:14-41). Init to `Date.now()` alongside
  `lastUserMs` (session.ts:60).
- In `preloadSessions` (session.ts:81-87), seed `lastActivityMs` from the last L2 turn's `t_ms`
  (restart-safe, mirrors the existing `lastUserMs` restore via `lastUserTurnMs`). Reuse
  `listRecentL2(id, 1)[0]?.t_ms` (the same source `proactiveTurn.lastInteractionMs` already uses),
  falling back to `lastUserMs`.
- Add a tiny `markActivity(session, nowMs)` helper (sets `lastActivityMs = max(current, nowMs)` — a
  clock is monotonic; never move it backwards).

**`packages/server/src/ws.ts`**
- At `chat.send` (ws.ts:233), in addition to `session.lastUserMs = Date.now()`, call
  `markActivity(session, now)`. (User message = activity + a reset anchor.)

**`packages/server/src/turn/runTurn.ts`**
- At turn finalize where the exchange is appended (`appendL2`, runTurn.ts:880), stamp
  `markActivity(session, Date.now())` for **every** turn that actually produced a reply — reactive,
  continuation, AND proactive. (Proactive already updates `lastProactiveMs`; also marking activity is
  harmless and keeps the single-timer invariant honest.) A turn that produced no reply (empty/failed,
  already dropped from persistence per v0.17.2) does not mark activity.

**`packages/server/src/proactive/ladder.ts`**
- Replace the gap computation (ladder.ts:75-78):
  ```ts
  const silenceGap = session.lastActivityMs > 0 ? nowMs - session.lastActivityMs : Infinity;
  const sinceProactive = cadence.lastProactiveMs > 0 ? nowMs - cadence.lastProactiveMs : Infinity;
  const effectiveGap = Math.min(silenceGap, sinceProactive);
  ```
  Behind the flag: when `LUNA_PROACTIVE_SILENCE_TIMER=0`, fall back to the old
  `userGap = nowMs - session.lastUserMs`. (One `silenceAnchorMs = timerOn ? lastActivityMs :
  lastUserMs` selector keeps the diff small.)
- The **escalation reset** (ladder.ts:87-94) stays keyed on `session.lastUserMs > cadence.lastProactiveMs`
  — unchanged. A user reply resets `phase → engaged`, `nudgesSent → 0`; Luna's own replies must NOT
  reset her escalation.

**`packages/server/src/proactive/cadence.ts`**
- `passesAntiSpam` idle floor (cadence.ts:77-80): measure `userGap` from the activity anchor. Extend
  `WakeContext` (cadence.ts:62) with `lastActivityMs` (or pass the resolved anchor from `fire.ts`);
  when the timer is on, the floor uses `lastActivityMs` so a long reactive turn no longer pre-elapses
  it. Keep `LUNA_PROACTIVE_IDLE_FLOOR_MS` (default 60_000).

**`packages/server/src/proactive/fire.ts`**
- Thread the activity anchor into the `passesAntiSpam` call (fire.ts:84) alongside the existing
  `lastUserMs`.

**No schema change.** `lastActivityMs` is in-memory session state (like `lastUserMs`), restored on
preload from the existing `l2_turns.t_ms`. No `packages/protocol` change, no migration.

## Tests

`packages/server/src/proactive/ladder.test.ts` + `cadence.test.ts` + `session.test.ts`:

- **The reported bug** — user msg at T0, reply finalized (marks activity) at T90, tick at T120:
  with the timer on, `silenceGap = 30s < ambientMinMs` → **no ambient**. With the flag off (old
  behavior), the same scenario **does** fire — pins the regression both ways.
- **Long-reply floor** — a reactive turn that finalizes 65s after the user message: at completion the
  idle floor (60s) is measured from `lastActivityMs` (the reply), so `passesAntiSpam` returns
  `mid_conversation`, not `ok`. (Off-flag: it wrongly returns `ok`.)
- **User reply still resets** — after `nudged`/`dormant`, a user message (`lastUserMs > lastProactiveMs`)
  → `phase = engaged`, `nudgesSent = 0`. Unchanged from Init 17's tests.
- **Dormant recovery from her last word** — `lastProactiveMs` recent, `lastActivityMs` recent → the
  1h recovery counts from the later of them (`min(silenceGap, sinceProactive)`), not from a stale
  user message.
- **Renudge backoff unaffected** — `nudged` phase still gates on `sinceProactive` vs the backoff
  ladder; `lastActivityMs` does not shortcut it.
- **Monotonic clock** — `markActivity` never moves `lastActivityMs` backwards given an out-of-order
  stamp.
- **Preload seed** — `preloadSessions` restores `lastActivityMs` from the last L2 `t_ms` (restart
  doesn't reset the silence gap to boot time).

Full suite stays green; `tsc` clean across packages.

## What this version explicitly does NOT include

- **Retuning the amplifiers** (ambientMin 120→300s, ambientProb 0.12→~0.06) → v0.29.1. v0.29.0
  changes only the *anchor*, so the fix is isolable and A/B-comparable via the flag.
- **Removing the old user-only-anchor path / deleting the flag** → v0.29.1.
- **Any change to reconnect/presence** — reconnection stays its own hook and does NOT bump the idle
  timer (design decision #1).

## Risk

- **Behavior-sensitive, live-facing.** Mitigated by the `LUNA_PROACTIVE_SILENCE_TIMER` flag (instant
  fallback to today's behavior) and by the fact that today's behavior is the *confirmed bug* — the
  proactive subsystem has never fired correctly live, so there is no good behavior to regress.
- **Double-bump ordering** — `markActivity` on both `chat.send` (turn start) and `appendL2` (turn
  finalize) is intentional and monotonic-safe; the finalize stamp is the meaningful one for "she just
  spoke".
- **Continuation timing** — a self-continuation (~4s after a user turn) marks activity when it speaks;
  this correctly extends the silence window past the continuation, matching intent.

## Acceptance criteria

- [ ] `Session` has `lastActivityMs`, seeded on preload from the last L2 `t_ms`.
- [ ] Every reply-producing turn (reactive/continuation/proactive) and every user message bump it.
- [ ] `ladder.ts` computes `silenceGap` from `lastActivityMs` when the flag is on; the old path is
      reachable via `LUNA_PROACTIVE_SILENCE_TIMER=0`.
- [ ] The anti-spam idle floor reads the activity anchor (no pre-elapse after a long reply).
- [ ] The escalation reset remains user-keyed; renudge/quota/dormant clocks unchanged.
- [ ] New tests above pass; full `bun test` green; `tsc` clean.
