# v0.28.2 — Pet window move + resize

> **Status: PLANNED.** Initiative: Desktop first-run & pet ergonomics (Order 3, version 3/3). Risk: **Medium**.
> Depends: **v0.28.1** (the model must be inert/half-body first). Flag: none — pet mode is the existing `?pet=1`.

## Goal

Make the pet window the thing you move and resize. Dragging on Luna's body **moves the OS window** (so you
place her anywhere on the desktop); resizing the window **scales the whole pet** (the half-body portrait
re-fits to the new size). This closes Alan's complaint — "桌宠模式 无法拖动或缩放窗口" — by moving the
move/resize affordance from the model (removed in v0.28.1) to the window itself.

## What ships

**Shell (`packages/desktop/src/main.ts`):**
- Pet `BrowserWindow` (`main.ts:94`): keep `transparent/frame:false/hasShadow:false/alwaysOnTop`, and **set
  `resizable: true` explicitly** (document it — today it's the implicit default and easy to lose). Add sensible
  `minWidth`/`minHeight` so she can't be resized to nothing, and `maximizable: false` (a maximized transparent
  pet is nonsense).
- **Reconcile click-through** (the hard part). Today `setIgnoreMouseEvents(true,{forward:true})` +
  `petHitTest.ts` makes the window pass-through except over her body/bar. That defeats both window-move
  (a drag region needs real events) and edge-resize (edges are in the ignored margin). **Recommended design
  (confirm with Alan — see Open questions):** drop per-pixel pass-through in pet mode. The window takes the
  mouse normally; her body becomes a `-webkit-app-region: drag` handle (move), the transparent margins host the
  OS resize border, and the bar/buttons are `-webkit-app-region: no-drag` + normal clickable. This trades the
  v0.26.2 "click through her margins to the desktop" nicety for real move/resize — the thing actually asked for.
  (If Alan wants to keep pass-through, the fallback is a narrow non-ignored resize-edge strip + a small drag grip;
  the plan flags this fork rather than guessing.)

**Web (`packages/web`):**
- `src/ui/theme.css`: in pet mode, `.luna-app.pet .model-stage` (her area) gets `-webkit-app-region: drag`;
  `.luna-app.pet .chat-input-row`, the dream/settings buttons, and the bubble stack get `-webkit-app-region:
  no-drag` (so you can still type / click / read without moving the window). The canvas keeps
  `touch-action:none` but no longer needs `cursor:grab` in pet mode (nothing to grab-drag on the model).
- `src/app.ts`: in the pet branch, **retire the per-pointermove `lunaPet.setIgnore` hit-test** (the
  `petHitTest.ts` driving) under the recommended design — the window is no longer pass-through, so the
  hit-test loop isn't needed. Keep `petHitTest.ts` + its tests (they may return if pass-through comes back);
  just stop wiring the loop. If the fallback design is chosen instead, keep the loop but exclude a resize-edge band.
- Model re-fit on resize is **already wired** (`sink:134` `globalThis.addEventListener('resize', fit)`), and
  v0.28.1 made `fit()` derive the half-body framing from live `host.clientWidth/Height` — so resizing the window
  re-fits the portrait with no new code. Verify only.

**Shell smoke (`main.ts` `smokeProbe`):** extend the go/no-go (mirroring the v0.27.2 `bridgeSetPetMode` pattern)
to assert, in pet mode, that `resizable === true` and that `.model-stage` carries `-webkit-app-region: drag`
(a computed-style probe), so a regression that silently breaks move/resize fails the smoke.

## Tests

- Shell: `resizable`/`minWidth`/`minHeight`/`maximizable` are set on the pet window (assert the `BrowserWindow`
  options object the plan factors into a pure `petWindowOptions()` helper — testable without launching Electron).
- Web: a pure assertion that pet-mode CSS marks `.model-stage` as `drag` and the bar/buttons as `no-drag`
  (snapshot the class→region intent via the layout builder, or a small mapping unit).
- Packaged pet smoke passes with the two new assertions (`resizable:true`, body is a drag region).
- Windowed mode untouched: `bun test` green; `tsc` ×4 clean.

## What this version explicitly does NOT include

- No per-pixel desktop click-through in pet mode (traded away under the recommended design — the window is a
  real, movable, resizable window). If Alan insists on keeping it, that's the flagged fallback, scoped larger.
- No "snap to screen edge" / multi-monitor placement memory / remembered pet size across restarts — a future
  polish (persist `win.getBounds()` to `settings.json`, the v0.27.0 shell store) once the core move/resize lands.
- No windowed-mode changes.

## Risk

- **Click-through removal is a visible behavior change** (you can no longer click "through" her transparent
  margins to the app behind). Mitigation: it's the explicit trade for move/resize, which is what was asked;
  flagged for Alan's confirmation before build (Open questions). Keep `petHitTest.ts` + tests intact so the
  decision is reversible.
- **`-webkit-app-region: drag` swallows DOM events** in its region — a stray interactive element inside
  `.model-stage` would become undraggable-and-unclickable. Mitigation: pet mode's model area has no controls
  (bar + buttons live outside it and are `no-drag`); verify no clickable element sits under the drag region.
- **Frameless resize affordance on macOS** can be finicky. Mitigation: the packaged smoke asserts `resizable`,
  and manual verify on the real `.app` (this is the one thing a headless probe can't fully prove — same
  standing "needs Alan's eyes" caveat as the rest of the desktop app).

## Acceptance criteria

- [ ] Pet mode: dragging on Luna's body moves the whole window across the desktop.
- [ ] Pet mode: resizing the window scales the pet; the half-body portrait re-fits and bubbles keep tracking.
- [ ] Pet mode: the input bar + dream/settings buttons are still clickable/typable (not swallowed by the drag region).
- [ ] `minWidth/minHeight` prevent resizing her to nothing; `maximizable:false`.
- [ ] Packaged pet smoke passes with the new `resizable` + drag-region assertions.
- [ ] Windowed mode unchanged.

## Notes for the next version (don't foreclose)

Persisting the pet window's bounds (position + size) belongs in the v0.27.0 shell store (`settings.json`) so she
reopens where you left her — keep `petWindowOptions()` able to accept a saved bounds override. If per-pixel
click-through is ever wanted back alongside move/resize, the `petHitTest.ts` seam is preserved for a hybrid
(pass-through only in a defined idle state).
