# v0.28.1 — Pet model fixed half-body

> **Status: PLANNED.** Initiative: Desktop first-run & pet ergonomics (Order 2, version 2/3). Risk: **Low**.
> Depends: nothing (pure web-frontend). Flag: none — gated by the existing `?pet=1` / `body.pet` state.

## Goal

In pet mode, stop treating the *model* as the thing you move and scale. Fix her as a **half-body
portrait** (head-to-waist, top-anchored, filling the pet window) that can't be dragged around inside the
window and can't be scroll-zoomed. This is the necessary precondition for v0.28.2 (where the *window*
becomes the move/resize handle): the model must be inert first, or window-drag and model-drag fight over
the same pointer. Windowed (non-pet) mode keeps full-body framing + drag + zoom exactly as today.

## What ships

**`packages/web/src/live2d/pixiLive2DSink.ts`:**
- `fit()` (`sink:114`) gains a **pet branch**. Today: `baseScale = (hostH * 0.92) / model.height` (full body,
  centered). Pet: scale so the **upper half** fills the window — anchor the top of the head near the top of the
  host and scale by width (`baseScale = (hostW * K) / model.width`, K tuned so shoulders-to-head read as a
  portrait), with the vertical base offset placing the crop at roughly the waist. The exact framing constants
  are a tune-in-preview detail; the structural change is "pet ⇒ width-fit + top-anchor, not height-fit + center."
- The pet flag reaches the sink via a small option on the sink factory (e.g. `createPixiLive2DSink(host, { pet })`)
  or a `setPetFraming(on)` method — chosen so `app.ts` (which already knows `?pet=1`) flips it. `fit()` reads it.
- **Disable model drag in pet mode**: the unconditional `pointerdown`/`pointermove` drag handlers (`sink:224–246`)
  become **no-ops when pet framing is on** (guard at the top of the handlers, or don't attach them). Persisted
  offset (`luna:live2d:pos`) is ignored for pet framing so a stray windowed-mode drag can't strand the portrait.
- **Disable scroll-zoom in pet mode**: the `wheel` handler (`sink:280–285`) guards on the pet flag and returns
  early (so v0.28.2 can later repurpose the window for scaling). Persisted zoom (`luna:live2d:zoom`) is not applied
  to pet framing.
- `updateHeadAnchor()` (`sink:176`) still publishes `--luna-head-*` + `--luna-model-*` CSS vars from the new
  framing, so the bubble stack + the pet click-through hit-test keep tracking her (they read those vars — no change
  needed there, they just get half-body values).

**`packages/web/src/app.ts`:** pass the pet flag into the sink when `?pet=1` (it already branches on pet for the
`body.pet` class + hit-test). No new state — reuse `isPet`.

**No shell change, no wire change, no schema change.** Windowed mode is byte-unchanged (the pet branch is only
taken under `?pet=1`).

## Tests

- `pixiLive2DSink` is DOM/WebGL-heavy; keep the unit-testable core pure: extract the framing math into a pure
  helper `petFraming(hostW, hostH, modelNaturalW, modelNaturalH) → { scale, baseX, baseY }` and test it —
  half-body scale fills width, top-anchored (baseY places the head near the top), independent of persisted
  offset/zoom.
- A guard test for the interaction gate: a tiny pure `interactionEnabled(pet) → boolean` (or equivalent) that the
  drag/zoom handlers consult, asserting `false` under pet, `true` otherwise.
- Existing sink/bubble/hit-test tests stay green (half-body still publishes the model-bbox vars `petHitTest.ts`
  consumes). `tsc` ×4 clean.

## What this version explicitly does NOT include

- No window move/resize — the window is still the fixed 560×900 frameless pet window from v0.26.2. This version
  only makes the *model* inert + half-body. Moving/resizing the window is v0.28.2 (which builds on the inert model).
- No change to windowed-mode framing/drag/zoom.
- No new setting/toggle for "half-body vs full-body in pet" — pet is always half-body (Alan's spec: "桌宠模式下
  live2d固定为半身"). A toggle is a future nicety if wanted.

## Risk

- **Framing tuning** (where the waist crop sits, how much headroom) is visual and needs preview iteration —
  verify on the isolated `:5273` preview with `?pet=1`, not by eye-in-code. Low blast radius (pet-only branch).
- **Bubble anchor drift**: the bubbles anchor off `--luna-head-*`; a top-anchored half-body moves the head up,
  so confirm bubbles still sit beside her head and don't clip the window top. Mitigation: the anchor math already
  derives from `model.x/width` + `HEAD_FRAC` — re-verify in preview.

## Acceptance criteria

- [ ] `?pet=1`: the model renders as a head-to-waist portrait filling the window width, top-anchored.
- [ ] `?pet=1`: dragging on her body does not move the model; scrolling does not zoom it.
- [ ] Windowed mode (`?pet` absent): full-body framing, drag, and scroll-zoom all work exactly as before.
- [ ] Speech bubbles still anchor beside her head in pet mode and don't cover her or clip off-window.
- [ ] `petFraming` unit test passes; suite green; `tsc` ×4 clean.

## Notes for v0.28.2 (don't foreclose)

Keep the pet-interaction gate (`interactionEnabled(pet)`) as the single place that says "model does not
consume pointer/scroll in pet mode" — v0.28.2 will hand that pointer/scroll to the WINDOW (drag to move,
resize to scale). Because `fit()` already re-runs on `globalThis 'resize'` (`sink:134`), the half-body portrait
will re-fit to any window size v0.28.2 introduces **for free** — don't hardcode the 560×900 pet size into the
framing math; derive everything from live `host.clientWidth/Height`.
